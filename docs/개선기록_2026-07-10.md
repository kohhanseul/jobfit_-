# 검색 품질 개선 기록 (2026-07-10)

하루 동안 한 개선 3개. 문제 -> 해결 -> 결과 순서로 정리

## 전체 요약

| 항목 | 전 | 후 |
|---|---|---|
| 데이터 | 직접 만든 가상 공고 3건 | 실제 공고 49건 (출처 URL 포함) |
| 품질 측정 | 불가 (평가 체계 없음) | 평가셋 10문항, hit@1/hit@3 측정 |
| hit@1 | 측정해보니 40% | 90% |
| 실사용 추천 | 무관한 직군 추천 + 근거 조작 | 프로필 맞는 신입 AI 공고 추천 |

---

## 1차: 실제 데이터 + 평가 체계

**문제**
- 데이터가 가상 공고 3건뿐 -> 3건 중 2~3건 반환하는 검색은 틀릴 수가 없음
- "의미 기반 검색" 이라는 주장을 검증할 방법이 없었음

**해결**
- 사람인 실제 공고 49건 수집 (전부 출처 URL, 수집일 기록)
- AI 직군만 넣지 않고 타 직군(건설, 영업, 네트워크, 하드웨어 등) 섞음 -> 검색이 골라내야 할 방해물
- 함정 공고 포함
  - AI 툴(Runway, Sora 등) 키워드 가득한데 직군은 영상 편집자인 공고
  - RAG, LangChain 요구하는데 경력 3년 이상인 공고
- 질문-정답 평가셋 10문항 + hit@1, hit@3 측정 스크립트(09_eval.py) 작성

**결과**
- 첫 측정: hit@1 40%, hit@3 50%
- 문제가 감이 아니라 수치로 보이기 시작함

---

## 2차: 임베딩 모델 교체

**문제**
- "영상 편집자 채용 공고 있어?" 같은, 정답 공고에 그대로 적혀 있는 질문도 틀림
- 여러 직무 한꺼번에 뽑는 잡탕 공고가 아무 질문에나 상위로 끌려나옴
- -> 검색 로직이 아니라 임베딩 모델(nomic-embed-text)의 한국어 표현력 문제로 진단

**해결**
- 다국어 임베딩 bge-m3로 교체
- 비교용으로 09_eval.py에 --embed-model 옵션 추가, 같은 평가셋으로 재측정

**결과**

| 임베딩 | hit@1 | hit@3 |
|---|---|---|
| nomic-embed-text | 40% | 50% |
| bge-m3 (채택) | 90% | 100% |

- 데이터 33건 -> 49건으로 늘려도(방해물 16건 추가) 90% / 100% 유지
- 함정 문항(영상편집 vs AI 개발, 경력직 구분)도 통과

## 3차: 실사용에서 발견한 검색 쿼리 결함

**문제**
- 평가 점수는 90%인데 실제 앱에 이력서 넣고 돌리니 무관한 직군(마케팅, 매장 보안) 추천됨
- 원인 추적:
  1. 앱이 이력서가 아니라 질문 문장만으로 검색하고 있었음. "내 이력서에 맞는 공고 추천해줘"에는 직무 정보가 0 -> 아무 질문에나 걸리는 범용 공고 반환
  2. LLM은 잘못 검색된 공고를 받아도 거부 안 함. 이력서에 없는 경험까지 만들어가며 적합한 척 정당화
  3. 평가셋 질문은 내용 있는 질문이라 이 결함이 평가에 안 잡힘 -> 벤치마크와 실사용 경로가 달랐던 것

**해결**
- 검색 쿼리를 질문 단독 -> 질문+이력서 본문으로 변경
- k=2 -> k=5 (LLM이 비교할 후보 확보)
- 프롬프트에 근거 규칙 추가: 제공된 공고 중에서만, 공고 번호 인용, 없는 경험 사용 금지, 경력 요건 불일치 명시, 맞는 게 없으면 없다고 답하기

**결과**
- 같은 이력서로 재실행 -> 상위 5건 전부 AI 직군 (대부분 신입 가능)
- 경력/스택 안 맞는 공고는 이유와 함께 "부적합"으로 분리됨

## 배운 것

- 평가셋 없으면 검색 품질은 그냥 주장. 측정이 있어야 개선이 있음
- RAG 품질은 LLM이 아니라 검색이 결정함. 검색이 틀리면 LLM은 틀린 걸 그럴듯하게 포장할 뿐
- 벤치마크 점수와 실사용 품질은 다를 수 있음. 평가가 실제 사용 경로를 지나는지 확인해야 함
- 직접 써보는 게(dogfooding) 제일 빠른 버그 발견 방법이었음
