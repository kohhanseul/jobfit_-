# Docker 컨테이너화 기록 (2026-07-14)

api 서버를 도커 이미지로 만들어서 어느 환경에서든 동일 실행되게 한 작업

## 문제

- 지금까지는 내 컴퓨터에서만 실행 가능 (파이썬 버전, 라이브러리 설치 상태에 의존)
- 다른 환경에서 돌리려면 환경 세팅부터 다시 -> "내 컴퓨터에서는 되는데" 문제
- 클라우드 배포하려면 어차피 컨테이너화가 선행되어야 함

## 준비 (환경 세팅)

- 도커는 리눅스 기반이라 윈도우에서는 WSL(Linux용 Windows 하위 시스템) 먼저 설치
  - 관리자 PowerShell에서 wsl --install -> 재부팅
- Docker Desktop 설치 (AMD64 버전. 일반 윈도우 PC는 전부 AMD64)

## 해결

**1. requirements-api.txt 분리**
- 전체 requirements.txt에는 tensorflow 등 api에 불필요한 무거운 패키지 섞여 있음
- api에 필요한 것만 분리 -> 이미지 용량과 빌드 시간 절약

**2. Dockerfile 작성**
- python:3.11-slim 베이스
- 의존성 목록을 코드보다 먼저 COPY -> 코드만 수정했을 때 설치 단계가 캐시로 건너뛰어져서 재빌드 빨라짐
- .dockerignore로 불필요한 파일(git, 캐시, 백업) 제외

**3. Ollama 주소 문제 해결 (오늘의 핵심)**
- 컨테이너 안에서 localhost는 컨테이너 자신을 가리킴 -> 호스트에서 도는 Ollama를 못 찾음
- 10_api.py의 Ollama 주소를 OLLAMA_BASE_URL 환경변수로 받게 수정
- 실행 시 -e OLLAMA_BASE_URL=http://host.docker.internal:11434 로 주입
  (host.docker.internal = 컨테이너를 실행한 호스트를 가리키는 도커 특수 주소)

## 결과 (실측)

- docker build 성공 (첫 빌드 약 1분)
- 컨테이너 실행 후 /health 정상: 공고 49건 로드 확인
- 컨테이너 안에서 /search 0.34초 -> 로컬 직접 실행과 동일 성능
- localhost:8000/docs 스웨거 화면도 컨테이너에서 동일하게 동작

## 배운 것

- 이미지(밀봉된 실행 환경)와 컨테이너(실행 중인 상태)의 구분
- localhost의 의미는 절대적이지 않고 실행 위치에 따라 달라짐
- Dockerfile에서 COPY 순서가 빌드 캐시 효율을 결정함
- 서빙 요건(FastAPI) + 재현성 요건(Docker)까지 확보. 남은 건 클라우드 배포
