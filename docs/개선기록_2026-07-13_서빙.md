# 서빙 계층 추가 + 검증 기록 (2026-07-13)

FastAPI로 API 서버(10_api.py) 추가하고 Swagger UI에서 실제 요청으로 검증한 기록

## 작업 요약

**문제**
- 스트림릿 화면으로만 쓸 수 있었음 (사람용)
- 다른 프로그램이 검색/분석 기능을 호출할 방법이 없었음

**해결: JSON 엔드포인트 3개**

| 엔드포인트 | 역할 | 비고 |
|---|---|---|
| GET /health | 서버 상태 + 공고 수 확인 | 배포 환경 생존 확인용 |
| POST /search | 이력서 기반 유사 공고 검색 | LLM 안 씀 |
| POST /analyze | 검색 + LLM 적합도 분석 | 스트림릿과 같은 근거 규칙 |

- 벡터 저장소는 서버 시작 시 1회만 구축 -> 전역 재사용
- 요청 형식 pydantic으로 검증 (필수 필드, k는 1~10 강제)
- /docs 자동 문서로 수동 테스트 환경 확보

**결과 (실측)**

| 항목 | 측정값 |
|---|---|
| /search 응답 | 약 0.4초 (공고 49건) |
| /analyze 응답 | 약 3분 (qwen3 8B, CPU 추론) |
| /search 상위 5건 | 전부 AI 직군, 신입 가능 공고 우선 |

/analyze 3분 = 로컬 CPU 추론의 한계. GPU 서빙이나 상용 API가 필요한 이유가 수치로 나옴

## 실사용 검증에서 확인한 것 2개

### 1. 빈 입력을 거절함 (우연히 확인)

- Swagger 테스트 중 이력서 칸에 견본 문자열 "string"이 그대로 전송된 적 있음
- LLM이 억지 분석 안 하고 "이력서 내용이 제공되지 않아 분석 불가"라고 답함
- 근거 규칙(없는 경험 금지, 억지 연결 금지) 넣기 전이었으면 의미 없는 입력에도 그럴듯한 분석을 지어냈을 상황 -> 규칙이 실전에서 작동한다는 증거

### 2. 오류 방향이 바뀜: 과대평가 -> 과소평가

- 정상 이력서로 분석하니 근거는 대체로 이력서에 실재하는 내용 기반, 불확실한 건 "부분적으로 부합" 표시
- 대신 새로운 유형의 오류 관찰됨
  - 이력서에 FAISS 있는데 "Vector DB 경험 없음" 판정 (FAISS = 벡터 DB라는 도메인 지식 연결 못함)
  - Ollama 로컬 LLM 경험을 LLM 활용 경험으로 인정 안 함
- 7/10 기록의 오류는 없는 경험을 만드는 과대평가였는데, 규칙 강화 후엔 있는 경험을 못 알아보는 과소평가로 이동
- 추천 도구에서 두 오류의 비용은 다름: 과대평가는 사용자가 잘못 지원하게 만들지만, 과소평가는 근거를 보고 스스로 바로잡을 수 있음 -> 안전한 방향의 오류로 이동한 것

**개선 방향**: 이력서를 자유 텍스트 대신 구조화 필드(기술 스택 목록)로 받아 도구명 매칭 보조, or 도메인 지식 강한 상용 API 모드 옵션
